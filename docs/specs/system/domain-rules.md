# ドメイン用語 ＆ ドメイン不可侵ルール

<!-- @spec:domain-rules -->

システム固有のユビキタス言語およびビジネス・データ不変条件の定義正本。共通技術制約は [../core-rules.md](../core-rules.md) を参照。

---

## 1. ユビキタス言語定義

<!-- @spec:domain-glossary -->

コード上の識別子（クラス・関数・型・CSSクラス・HTML要素）および仕様書内の語彙は以下の定義に統一する (**MUST**)。

| 用語 | コード識別子 | 厳密な定義・責務 | 混同しやすい概念との境界 |
| :--- | :--- | :--- | :--- |
| **Readable HTML** | `readable-html` / `template.html` | 要約・構造再編・図解・トレーサビリティを備えた単一のポータブルHTMLドキュメント。 | 単なるMarkdownからHTMLへの字面通りのレンダリング結果とは異なる。 |
| **トレーサビリティ** | `traceability` / `.badge-*` | 生成HTMLの各セクション・要件と元仕様テキストとの対応関係（Preserved, Summarized, Inferred, Assumption, Open Question）。 | 単なる元文書へのハイパーリンクではなく、情報の加工・推論状態の明示。 |
| **デザイントークン** | `Design Tokens` / `:root --color-*` | カラー、タイポグラフィ、角丸、余白などのUIテーマを統一管理するCSSカスタムプロパティ群。 | ハードコードされたインラインスタイルとは区別する。 |
| **図ビューア** | `diagramModal` / `.diagram-container` | キーボード操作・ホイールズーム/パン・マウスドラッグに対応したSVG/Mermaid図のモーダル拡大表示機能。 | 静的な画像埋め込みやブラウザ標準のスクロール操作とは区別する。 |

---

## 2. ドメイン不変条件 ＆ 検証基準

<!-- @spec:domain-invariants -->

| ルールID | 対象エンティティ / 領域 | ドメイン不変条件契約 (`MUST` / `MUST NOT`) | 機械的検証基準 |
| :--- | :--- | :--- | :--- |
| `DOM-01` | 仕様書テキスト / 要件 | 元仕様の規約キーワード（`MUST`, `SHOULD`, `MAY`, `required`, `optional`）およびAPI識別子・型・制約・コードブロックは勝手に改変・削除してはならない (**MUST**)。 | 要約後ドキュメント内に元仕様の必須識別子およびキーワードが保持されていること。 |
| `DOM-02` | 推論・補足情報 | 入力仕様の未確定事項や推論による補足は、必ず `Inferred`, `Assumption`, または `Open Question` バッジで明示的に区別しなければならない (**MUST**)。 | 推論セクションに未分類の断定表現が含まれず、所定のバッジが付与されていること。 |
| `DOM-03` | HTML生成 / 入力データ | 外部仕様テキストのHTML埋め込み時は特殊文字（`&`, `<`, `>`, `"`, `'`）のエスケープを必須とし、未検証のHTML/JS実行を禁じる (**MUST NOT**)。 | 生成HTMLソースにおいて未エスケープのスクリプトタグや危険なイベントハンドラが `0` 件であること。 |
| `DOM-04` | 図解レンダリング | Mermaid図を使用する場合はCDN依存を明記し、完全自己完結/オフライン指定時はインラインSVGへ置換しなければならない (**MUST**)。 | オフライン指定時、生成HTMLに外部CDN参照（`<script src="https://...">` 等）が含まれないこと。 |
